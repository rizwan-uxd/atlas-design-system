# M3: the registry, and three-way agreement (implementation plan)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan
> task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `packages/registry` exists as the source of truth shared by the code-authoring harness and the
future runtime. The authored half declares what neither Figma nor code models; the generated half is
harvested from the real TypeScript types, Code Connect and `atlas/metadata`; one invariant
(`registry-build --check`) keeps the authored half a subset of the generated one.

**Architecture:** `scripts/registry-build.mjs` builds one TypeScript program over the components that
have an authored entry, reads each `<Name>Props` with `getPropertiesOfType` (own, inherited and every
`on*` handler), parses Code Connect with the same compiler for slots and Figma-state → prop mappings,
and copies Figma axes and `tokensUsed` from `atlas/metadata`. It writes `generated/<Name>.facts.json`
(committed, git-diff gated by `--check`) and never writes `atlas/`. Authored entries are validated by
a JSON Schema in `packages/governance/schemas/registry.schema.json` through the existing
`design/schemas` check; the subset invariant lives in `scripts/lib/registry.mjs` so it is unit-tested
without a program build.

**Tech stack:** Node ESM, `node:test`, `typescript` compiler API (devDependency), `ajv@8` (already
declared, through `scripts/lib/schemas.mjs`).

## Global constraints
- Roadmap §2c (`docs/ATLAS-DELIVERY-ROADMAP.md`) is the spec. Exit (M3, end of all sessions): ≥6 types
  with `registryComplete: true` (Form, TextField, Button, Alert, Field, Text); all 47 have a generated
  contract; "typed event contracts" and "components with declared fallback" move to *passing*.
- **The authored registry is always a subset of the generated facts, never a superset.**
- `registry-build` *reads* `atlas/`, never writes it. No Figma calls. No change under
  `packages/ui-web/src` (R9: the registry lane must not touch components).
- Every new `packages/registry/**/*.json` has a schema and an `INPUTS` rule in the same commit (M2).
  A new `atlas-verify` check returns `inspected`/`scope`.
- Never invent a design-system rule (`AGENTS.md` §6). A field that needs an owner decision (a
  component's `fallback` target, `nesting`, `a11y`, `responsive`, `capabilities`) is left absent, and
  `registryComplete` stays `false` until it is decided.
- M1's comparator stays two-way until the session that fills its `registry` slot; it is renamed
  `design/figma-registry-code` in that same commit and not before.
- No optional chaining on data under test; absence is a failure that names the file and field.
- Verification order: token-lint → tsc → vitest → test:scripts → atlas:verify.

## Decisions taken in this plan (recorded so a later session does not re-litigate them)
1. **Entries are keyed by the registered type.** `src/<Type>.registry.json` has `type` = file name.
   `aliasOf` is the `ui-web` component it renders (`"Button"` for Button, `"Input"` for TextField),
   or `null` for a `kind: "structural"` type. `aliases.json` is the alias table (north-star name →
   component, or `"structural"`). `--check` FAILs when they disagree: an entry whose `type` differs
   from its `aliasOf` must appear in `aliases.json` with that target, an alias with an entry must match
   it, and every alias target must be a component in `atlas/metadata` or `"structural"`.
2. **Facts are generated for every component in `atlas/metadata`** (revised in session 2; session 1
   generated them only for the components an entry renders). Contracts need all 47, and an entry
   is not a precondition for a fact.
3. **Generated per-component schemas (`generated/schemas/`) are exempt from `INPUTS`**, like
   `packages/governance/schemas/`: they are JSON Schema documents, not data. `registry-build` compiles
   each with ajv in strict mode, which validates it against the 2020-12 meta-schema, and `--check`
   diff-gates them. The exemption lands with the directory (session 3), not before.
4. **Own props must be accounted for.** Every own prop (declared in the component's file) is in
   `protocolProps`, `slots` or an `events` handler, or in `hiddenProps` with a reason. A gap is WARN, and FAIL at
   `registryComplete: true` (the roadmap's per-component ratchet). Inherited DOM props are visible to
   the invariant (so `disabled` and `onClick` can be declared) but never required.
5. **`states` classifies every Figma `State` member** as `interaction` (CSS-driven: hover, focus,
   active, default) or `prop` (named in `stateProps`). Unclassified or extra members FAIL.
6. **Facts files inline arrays of scalars on one line**, so a 300-prop component stays a reviewable
   diff.

## File structure

| File | Responsibility |
|---|---|
| `packages/registry/aliases.json` (new, authored) | `TextField`→`Input`, `Modal`→`Dialog`, `Form`→`structural` |
| `packages/registry/src/<Type>.registry.json` (new, authored) | the declarative half; session 1: Button, TextField, Alert, Form |
| `packages/registry/generated/<Name>.facts.json` (new, generated) | props, events, slots, Figma axes, tokensUsed |
| `packages/governance/schemas/registry.schema.json` (new) | `$defs`: `aliases`, `entry`, `facts` |
| `scripts/lib/schemas.mjs` | three `INPUTS` rules |
| `scripts/lib/registry.mjs` (new) | `extractFacts(program, …)`, `codeConnectFacts(src)`, `checkRegistry({entries, aliases, facts, metadata, cssTokens})`, `formatJson` |
| `scripts/registry-build.mjs` (new) | CLI: write facts, or `--check` (stale facts + invariant) |
| `scripts/tests/registry.test.mjs` (new) | invariant, Code Connect harvest, fact extraction on a fixture program |
| `.github/workflows/ci.yml` | `registry-build --check` step in the Atlas Verify job |
| `package.json` | `registry:build`, `registry:check` scripts |

## Session 1 tasks (this session)

### Task 1: Schema, aliases, INPUTS rules
- `registry.schema.json`: `aliases` (object, `_note` + `aliases`: name → component name or
  `"structural"`); `entry` (required `type`, `aliasOf`, `kind`, `platforms`, `registryComplete`;
  optional `composedOf`, `protocolProps`, `hiddenProps`, `events`, `slots`, `states`, `stateProps`,
  `tokenRoles`, `fallback`, `nesting`, `a11y`, `responsive`, `capabilities`; `additionalProperties:
  false`; `kind: "structural"` ⇒ `aliasOf: null` and `composedOf` required; `kind: "component"` ⇒
  `aliasOf` a component name; `registryComplete: true` ⇒ every declarative field required); `facts`
  (generated shape, `additionalProperties: false`).
- `INPUTS`: `packages/registry/aliases.json` (required), `packages/registry/src/*.registry.json`
  (`min: 1`), `packages/registry/generated/*.facts.json`.
- Tests (`schemas.test.mjs`): committed files validate; a structural entry with an `aliasOf`, an entry
  with an unknown field, and `registryComplete: true` with no `fallback` each fail naming the pointer.

### Task 2: Fact extraction
- `extractFacts(program, file, name)` → `{ name, import, source, props, inherited, events, unions }`:
  `props` = own props `{ name, type, optional }`; `inherited` = `{ <declaring interface>: [names] }`;
  `events` = every `on[A-Z]*` prop `{ name, type }` (own or inherited); `unions` = for any prop whose
  non-nullable type is a union of string literals, `{ <prop>: [members] }`.
- `codeConnectFacts(src)` (TS AST over `packages/figma-sync/code-connect/<Name>.figma.tsx`) →
  `{ instances: { <prop>: <Figma layer> }, stateProps: { <Figma State member>: <prop> }, enums:
  { <prop>: <Figma axis> } }`.
- Facts add `figma: { nodeId, axes }` and `tokensUsed` from `atlas/metadata/<Name>.json`.
- Tests: a fixture `.tsx` extending `React.ComponentProps<"button">` yields `onClick` in `events` and
  `disabled` in `inherited`; an `Omit<…>` base still reports its interface; Code Connect harvest on
  Button's real file returns both icon instances and `loading`/`disabled` state props.

### Task 3: The invariant
`checkRegistry` returns `{ fail: [], warn: [], inspected }`. FAIL (authored side) on:
`protocolProps` entry with no generated prop; an enum member absent from the code union; an authored
enum narrower than the union without `narrowed`; an `events` handler absent from generated `events`;
a slot that is neither a `ReactNode`/function-typed prop nor a Code Connect instance; a `fallback`
type that is not registered; a `tokenRoles` value missing from `atlas.tokens.css` or from that
component's `tokensUsed`; a `stateProps` value with no generated prop; `states` ≠ the Figma `State`
members; any alias-table disagreement (decision 1); a `composedOf` member that is not a component;
missing facts for an entry's `aliasOf`. WARN: an own prop in neither `protocolProps` nor
`hiddenProps` (FAIL at `registryComplete: true`). One table-driven test per rule, PASS and FAIL.

### Task 4: CLI, authored entries, CI
- `registry-build.mjs` writes facts; `--check` regenerates in memory, FAILs on any byte difference
  ("run npm run registry:build"), then runs `checkRegistry`, prints `PASS (N entries, M facts, K
  checks)` and FAILs on zero entries.
- Author Button, TextField, Alert, Form from existing sources only: enums from Code Connect and
  Figma, events from real handlers, slots from Code Connect instances and `ReactNode` props,
  `tokenRoles` from the existing component-token layer (Button, Input; Alert uses private vars and is
  left to Phase 2d), `states` from Figma `State`. `registryComplete: false` on all four, because
  `fallback`, `nesting`, `a11y` and `responsive` need owner decisions.
- CI step after Script tests: `node scripts/registry-build.mjs --check`. Assert it in
  `ci-workflow.test.mjs`.
- Negative test 6 from the roadmap (author an enum member absent from the code union) is a script
  test, and is demonstrated once against the real repo and reverted.

## Session 2 (done 2026-10-23)
- **Facts for all 47.** Two components (Drawer, Sheet) export no `<Name>Props`, and five bind a
  sub-part in Code Connect, so facts no longer look up `<Name>Props`. Decision 7: **the part is the
  element Code Connect's `example` drives with the mapped Figma props**, in the one `figma.connect`
  whose node-id equals `figmaNodeId` (`<DrawerContent side={side}>` while `Drawer` is bound); props
  are read from that part's call signature, i.e. `React.ComponentProps<typeof Part>`. No connect for
  the node → FAIL. Facts record `part`, `propsType` and `codeConnect.bound`.
- **Contracts for all 47**, generated to `packages/governance/contracts/generated/<Name>.contract.ts`
  (decision 8: next to the hand-written ones until session 4 moves them into the same paths) plus
  `_assert.ts`. One named type alias per assertion, so tsc names what broke: `Own_<prop>`,
  `Optional_<prop>` (optionality flip), `Union_<prop>` (tuple-form exact match), and
  `Registry_<Type>_<prop>` for each entry's protocolProps and handlers. `--check` FAILs on a missing,
  stale or orphaned contract.
- **Proven on the real Button and as script tests:** deleting `"link"` from `ButtonVariant` or
  deleting `iconOnly` fails the generated contract while `Button.contract.ts` stays silent (the two
  roadmap holes); making `iconOnly` required also fails.
- **Audit, generated vs hand-written (the roadmap's "free audit").** No real drift: every union member
  and prop the 44 hand contracts assert matches the code. Coverage gaps, now closed by generation:
  Breadcrumb, DropdownMenu, ListItem had no contract; 26 own props across 11 components were guarded
  by nothing (Card aria-label; Checkbox aria-describedby, className; CommandMenu children; Image
  className, fallback, style; NavBar style; Progress 4 aria props; SidebarMenuRow children, href;
  Slider 3 aria props; StatCard disabled, onClick; Tabs activeTab, children, defaultTab, items,
  onTabChange; Textarea required, showCount). **Open gap, blocks session 4's deletion for 10
  components:** their hand contracts also guard sub-parts the generated ones do not — Avatar
  (AvatarGroupProps), ButtonGroup (ButtonGroupButton/IconButtonProps), Card (CardHeaderProps),
  CommandMenu (CommandMenuProps, Group, Item), DatePicker (DatePickerProps single/range branches,
  Content, Input, NaturalInput), RadioGroup (RadioGroupItemProps), Select (SelectProps,
  SelectItemProps), SidebarMenuRow (SidebarMenuRowChildProps), Table (TableCellProps, TableRowProps),
  Tabs (TabsRootProps).

## Session 3 (done 2026-10-23)
- **Protocol schemas**, one per registry entry, in `packages/registry/generated/schemas/<Type>.schema.json`:
  `{ type, props, slots }`, closed at every level, so an unknown prop, a hidden prop (`asChild`), a
  raw `style` or an undeclared slot is invalid. `props` are exactly the entry's protocolProps: enums
  from `values`, everything else typed from the code's real (also inherited) prop type. A type with no
  JSON-representable member (`ReactNode`, a handler) FAILs the build rather than being dropped;
  non-JSON members of a union are dropped (`value: string | number`, not `readonly string[]`).
  Decision 3 is built: the directory is exempt from `INPUTS`, and each schema is compiled by ajv in
  strict mode, which checks it against the 2020-12 meta-schema.
- **`generated/componentMap.ts`**: registered type → component through deep imports (`TextField: Input`),
  plus `structuralTypes` and a `RegisteredType` union. `packages/registry/**/*.ts` joined the root
  `tsconfig.json`, so `tsc` proves every import resolves.
- **`scope/no-new-components`** now also inspects registry entries added since `--base`: an entry
  passes when it renders a real component (directly or through `aliases.json`) or is structural;
  anything else needs the `atlas-approved-new` label (`--allow-new-component`). An invalid entry fails
  closed.
- `--check` diff-gates schemas and the map with the facts and contracts.
