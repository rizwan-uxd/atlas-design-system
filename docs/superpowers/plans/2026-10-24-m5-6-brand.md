# M5.6 — Brand axis (Atlas + Warm) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a brand axis with a second brand, **warm**, built on Figma's coral ramp. A brand changes **colour only**: six semantic colours, in light and dark. The roadmap rows "All supported brand modes compile" (`design.brand-modes`) and "Visual regression per brand mode" (`visual > sandbox`) become measurable.

**Architecture:**
- **Figma (gate 2):** a new collection `Atlas/Brand` with modes `Atlas` and `Warm` holds the six brand colours twice, once per theme (`light/*`, `dark/*`: 12 variables). `Atlas/Semantic` re-points those six colours' Light and Dark values at them, which is value-identical for Atlas. The 9 coral primitives used get WEB code syntax.
- **PR-0 (no Atlas visual change):**
  - 9 coral primitives and two `[data-brand="warm"]` blocks in `atlas.tokens.css`
  - the component-token block also declared on `[data-brand]`
  - the contrast parser and check learn brands, so warm-light and warm-dark are measured
  - a new `design.brand-modes` check
- **PR-1:** a sandbox brand toggle and warm screenshots in the visual suite. The new baselines come from `visual-baseline.yml` in their own PR.

**Tech Stack:** CSS custom properties · `scripts/lib/contrast.mjs` · `scripts/atlas-verify.mjs` · node:test · vitest · Figma MCP `use_figma` · Playwright.

## Global Constraints

- **Kind B: changes visuals by design (roadmap M5.6).** Atlas (the default brand) must not change: the existing light and dark baselines stay byte-identical, and a changed Atlas baseline is a bug. Warm adds **new** baselines (`warm-light-*`, `warm-dark-*`), reviewed as images in the `visual-baseline.yml` PR.
- **Owner decisions (2026-10-24):** brands are Atlas and one warm brand; a brand changes **colour only**; the warm ramp is **coral**; the brand is named **warm** (`data-brand="warm"`, Figma mode `Warm`).
- **Brand-varying colours (owner-approved mapping):**

|---|---|---|---|---|
| `--atlas-primary` | brand-600 | coral-600 | brand-500 | coral-400 |
| `--atlas-primary-hover` | brand-700 | coral-700 | brand-400 | coral-300 |

- **Selector rules (the subtree lesson from M5.5):**
  - **Warm light:** `[data-brand="warm"]`, specificity (0,1,0), placed after the Atlas dark block.
  - **Warm dark:** `[data-brand="warm"]:is([data-theme="dark"], .dark), [data-brand="warm"] :is([data-theme="dark"], .dark), :is([data-theme="dark"], .dark) [data-brand="warm"]`, specificity (0,2,0), placed after warm light. It must beat both Atlas dark (0,1,0) and warm light, whether brand and theme sit on the same element, brand is an ancestor, or theme is an ancestor.
  - **Component-token block:** its selector becomes `:root, [data-theme="dark"], .dark, [data-brand]`. All 25 aliases of `primary`/`focus-ring` live in that block, so without this a brand set on a subtree would keep Atlas blue in buttons and checkboxes.
  - **Block order constraints:**
    - `convert-tokens.mjs` reads the **first** `[data-theme="dark"]` occurrence, and `atlas-sync` slices between "Semantic · Light" and "Dark theme override". So the brand blocks go after the Atlas dark block and its closing brace, before the shadow-role block.
    - `tokens:build` must leave the native file unchanged, so no `atlas-native-thaw` label.
- **Contrast parser hazard:** today `parseTokens` puts any selector containing `[data-theme="dark"` into Atlas **dark**, so the warm-dark block would silently overwrite Atlas dark values. The parser must exclude brand-scoped selectors from the base maps before any CSS change (Task 2 precedes Task 3).
- **Figma:**
  - `Atlas/Brand` variables carry the same scopes as the semantic colour they feed and have **no WEB syntax**: Figma-only, listed as `unpublished`. The CSS spells brands as selector blocks, not as tokens.
  - Brand names must match across Figma and CSS: Figma mode `Warm` ↔ CSS `warm`, lowercased.
- **Out of scope:**
  - `foreground-on-brand` (the Switch thumb) stays white. On warm dark, the thumb against the coral-400 track measures about 2.4:1. This is a gate-2 visual review item, logged as a candidate if the owner wants it changed.
  - The runtime demo gets no brand screenshots, because the metric names `visual > sandbox`.
  - `packages/ui-native`.
- Branch from `main` after #117 (M5.5) merges. No new component. CSS tokens added: the 9 coral primitives only.

### Task 2: The contrast parser and check learn brands

**Files:** `scripts/lib/contrast.mjs` (`parseTokens`, `contrastCheck`) · `scripts/atlas-verify.mjs` (`code.contrast`, ~line 445: its note divides measurements by 2 and says "light+dark"; divide by the number of distinct `p.theme` values and list them) · Test: `scripts/tests/contrast.test.mjs`

**Interfaces:**
- Produces: `parseTokens(css) → { light: Map, dark: Map, brands: { [name]: { light: Map, dark: Map } } }`. A selector carrying `[data-brand="x"]` never joins the base maps. Within a brand, a selector also carrying `[data-theme="dark"]` or `.dark` joins `dark`; otherwise `light`.

// M5.6 — metric `design.brand-modes` ("All supported brand modes compile successfully"): every
// [data-brand] block overrides the same colours in light and dark, each declared in :root and each
// resolving to a colour, and the Figma Atlas/Brand modes name exactly the CSS brands (DEC-091).
check("design", "brand-modes", () => {
  const t = parseTokens(read(TOKEN_CSS))
  const names = Object.keys(t.brands).sort()
  const fails = []
  if (!names.length) fails.push(`${TOKEN_CSS} declares no [data-brand] block — there is no brand axis to compile`)
  let inspected = 0
  for (const b of names) {
    const { light, dark } = t.brands[b]
    const l = [...light.keys()].sort(), d = [...dark.keys()].sort()
    if (l.join() !== d.join()) fails.push(`${b}: light and dark override different colours — light ${l.join(" ")} · dark ${d.join(" ")}`)
    for (const [theme, own, map] of [["light", light, new Map([...t.light, ...light])], ["dark", dark, new Map([...t.light, ...t.dark, ...light, ...dark])]]) {
      for (const name of own.keys()) {
        inspected++
        if (!t.light.has(name)) fails.push(`${b} ${theme}: ${name} is not declared in :root — a brand may only override existing tokens`)
        else if (!resolveColor(name, map).color) fails.push(`${b} ${theme}: ${name} does not resolve to a colour`)
      }
    }
  }
  const col = (inputs.valid("atlas/tokens.json") ?? JSON.parse(read("atlas/tokens.json")))?.figmaTable?.collections?.find((c) => c.name === "Atlas/Brand")
  const figma = (col?.modes ?? []).map((m) => m.toLowerCase()).filter((m) => m !== "atlas").sort()
  if (!col) fails.push("atlas/tokens.json figmaTable has no Atlas/Brand collection — pull the variable table")
  else if (figma.join() !== names.join()) fails.push(`Figma Atlas/Brand modes (${figma.join(", ") || "none"}) do not match the CSS brands (${names.join(", ") || "none"})`)
  return { ...verdict(fails), inspected, scope: names.length }
})
