# M5.3 — Semantic type tier Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add eight composite text roles, each a size + line-height + weight bundle (+ letter-spacing for overline). Back each role with a Figma text style, and move every component text rule whose meaning fits onto a role. Every pixel that moves is listed below before any code is written.

**Architecture:**
- **PR-0** creates the role variables and the eight text styles in Figma, re-syncs the variable table, and adds the CSS role tokens `--atlas-type-<role>-size|line-height|weight` (plus `--atlas-type-overline-letter-spacing`) as aliases of existing tokens. Nothing consumes them yet, so there is no visual change.
- **PR-1** rewrites the 46 mapped rules so each sets the full role, and adds the token-lint ratchet `semantic-type`. Its visual changes go to a separate baseline PR from `visual-baseline.yml`, reviewed as images.

**Tech Stack:** CSS custom properties · `packages/governance/token-lint.mjs` · `scripts/lib/token-rules.mjs` (pure, `node:test`) · JSON Schema 2020-12 · Figma MCP `use_figma` (variables + text styles) · Playwright visual job and `visual-baseline.yml` (CI).

## Global Constraints

- **Kind B: value-changing migration (roadmap M5).** No zero-diff claim. The plan names, before any code, which components and baselines are expected to change and why (§ Expected changes).
  - An unlisted change is a bug and fails review.
  - Baselines are regenerated only through `visual-baseline.yml`, in their own PR, never bundled with the CSS change.
  - The accepted change is recorded as DEC-088 with before/after values.
  - A Kind B stage must not hide its changes behind compatibility aliases that keep the old values.
- **Figma first:** the roles exist in Figma as variables and text styles, and the changed text is approved in Figma (gate 2) before code.
- **Role set (owner, 2026-10-24):**

| Role | Size | Line-height | Weight | Extra | Meaning |
|---|---|---|---|---|---|
| `type-heading` | `text-h3` (responsive 18/22/24) | `tight` 1.2 | `semibold` | | modal and dialog titles |
| `type-title` | `text-h4` (responsive 16/18/20) | `snug` 1.35 | `semibold` | | card and panel titles |
| `type-body` | `text-body` 16 | `normal` 1.5 | `regular` | | running text |
| `type-body-sm` | `text-body-sm` 14 | `normal` 1.5 | `regular` | | descriptions, menu and table text |
| `type-label` | `text-body-sm` 14 | `normal` 1.5 | `medium` | | item, option and field labels |
| `type-caption` | `text-caption` 12 | `normal` 1.5 | `regular` | | helper, meta, legend, tooltip |
| `type-overline` | `text-caption` 12 | `normal` 1.5 | `medium` | `letter-spacing-wide` | section labels, group labels, shortcuts |
| `type-stat` | `font-size-3xl` 30 | `tight` 1.2 | `semibold` | | chart and stat values |

- **CSS names:** `--atlas-type-<role>-size`, `--atlas-type-<role>-line-height`, `--atlas-type-<role>-weight`, plus `--atlas-type-overline-letter-spacing`, for 25 tokens in total. Each is one `var()` alias of an existing token. Sizes alias the responsive `--atlas-text-*`, so the `@media` uplift keeps working without new `@media` blocks.
- **Control text stays on component tokens.** Button, Input, Select, Textarea, OtpInput and Tabs `font-size` keep their per-size component tokens: a role is not a size scale.
- A rule moves to a role only when its *meaning* fits. Matching the value is not enough. No new component and no token beyond the 25. `atlas/` is regenerated, except `atlas/state/decisions.json` and `candidates.json`, which are appended.
- **Branch from `main` after #112 (M5.2) merges.** M5.3 shares `token-primitives.allow.json` and the token-lint wiring with it.

### Task 1 (gate 1 → 2): Variables, text styles and the Figma change

**Files:** Figma file `cKYhfaHLCoyMHi9nKr63Ig` only.

> **As built (2026-10-24):**
> - **Binding units.** A probe style showed that Figma reads a *bound* line-height or letter-spacing FLOAT as **pixels** (line-height/normal 1.5 became a 1.5px line height). The owner chose **static percent**: `Type/*` styles bind `fontSize` and `fontWeight` to the role variables, and carry line-height (120/135/150%) and letter-spacing (overline 2%) as fixed percents equal to the CSS. The line-height and letter-spacing role variables exist with WEB syntax but unbound, and their scopes are empty like their primitives', so nobody binds them as pixels. Record this in DEC-088.

> - **Styles:** `Type/Heading|Title|Body|Body-sm|Label|Caption|Overline|Stat`, in Nunito Sans.
> - **Applied** to 881 text layers in 26 components, plus their nested source components:
>   - Chart Stat, Chart Legend Item, BreadcrumbItem, Dropdown Menu Item, Password strength, Step, Radio Group Item
>   - A style is applied only where the layer's size equals the role size, so size-variant layers are untouched.
> - **What changed in Figma** is exactly the listed set:

- [ ] **Step 1: Write the failing test.** It asserts that each of the 25 tokens is declared once, in `:root`, as exactly `var(<the table's source token>)`, and is never overridden in `@media` (the uplift lives on `--atlas-text-*`).

```ts
// packages/ui-web/tests/tokens-type-roles.test.ts
// M5.3 (Kind B): every type role field is an exact alias of an existing token; the responsive uplift stays on --atlas-text-*.
import { readFileSync } from "node:fs"
import { resolve } from "node:path"
import { describe, expect, it } from "vitest"

const css = readFileSync(resolve(__dirname, "../../tokens/atlas.tokens.css"), "utf8")
const ROLES = {
  heading: ["text-h3", "line-height-tight", "font-weight-semibold"],
  title: ["text-h4", "line-height-snug", "font-weight-semibold"],
  body: ["text-body", "line-height-normal", "font-weight-regular"],
  "body-sm": ["text-body-sm", "line-height-normal", "font-weight-regular"],
  label: ["text-body-sm", "line-height-normal", "font-weight-medium"],
  caption: ["text-caption", "line-height-normal", "font-weight-regular"],
  overline: ["text-caption", "line-height-normal", "font-weight-medium"],
  stat: ["font-size-3xl", "line-height-tight", "font-weight-semibold"],
} as const
const decls = (name: string) => [...css.matchAll(new RegExp(`${name}\\s*:\\s*([^;]+);`, "g"))].map((m) => m[1].trim())

describe("type roles", () => {
  for (const [role, [size, lh, wt]] of Object.entries(ROLES)) {
    for (const [field, src] of [["size", size], ["line-height", lh], ["weight", wt]] as const) {
      it(`--atlas-type-${role}-${field} aliases --atlas-${src}`, () => {
        expect(decls(`--atlas-type-${role}-${field}`)).toEqual([`var(--atlas-${src})`])
      })
    }
  }
  it("--atlas-type-overline-letter-spacing aliases --atlas-letter-spacing-wide", () => {
    expect(decls("--atlas-type-overline-letter-spacing")).toEqual(["var(--atlas-letter-spacing-wide)"])
  })
})
```

### Task 3: The `semantic-type` ratchet

**Files:** `scripts/lib/token-rules.mjs` · `packages/governance/token-lint.mjs` (rule 13) · `governance.schema.json` (`family` enum adds `"type"`, `token` pattern adds `font-size|text`) · `scripts/tests/token-rules.test.mjs`

**Interfaces:** `semanticTypeViolations(files, allow) → { violations, inspected }`, the same contract as `semanticSpacingViolations`. It reads only `font-size` declarations. In component CSS, a `font-size` that names `--atlas-font-size-*` or `--atlas-text-*` fails unless allowlisted with a reason and exact count. A component token (`--atlas-button-size-md-font-size`), a role (`--atlas-type-*-size`), a private var and `inherit`/`1em` are legal.

- [ ] **Step 1: Write the failing tests**

```js
test("semantic type: a role or a component token passes; a primitive scale step fails", () => {
  const ok = ".a { font-size: var(--atlas-type-label-size); } .b { font-size: var(--atlas-button-size-md-font-size); } .c { font-size: 1em; }"
  assert.deepEqual(semanticTypeViolations([{ file: F, src: ok }], []).violations, [])
  const { violations } = semanticTypeViolations([{ file: F, src: ".x {\n  font-size: var(--atlas-font-size-sm);\n}" }], [])
  assert.equal(violations[0].line, 2)
  assert.match(violations[0].text, /--atlas-font-size-sm.*type role/)
})

test("semantic type: only font-size is read", () => {
  assert.deepEqual(semanticTypeViolations([{ file: F, src: ".x { --_h: var(--atlas-text-h3); line-height: var(--atlas-line-height-tight); }" }], []), { violations: [], inspected: 0 })
})

test("semantic type: exact count per file and token; a changed count or stale entry fails", () => {
  const allow = [{ family: "type", file: F, token: "--atlas-text-caption", count: 1, reason: "badge size variant" }]
  const one = ".sm { font-size: var(--atlas-text-caption); }"
  assert.deepEqual(semanticTypeViolations([{ file: F, src: one }], allow).violations, [])
  assert.match(semanticTypeViolations([{ file: F, src: one + one }], allow).violations[0].text, /2 uses, allowlist says 1/)
  assert.match(semanticTypeViolations([{ file: F, src: ".a {}" }], allow).violations[0].text, /stale allowlist entry/)
})

test("semantic type: a spacing allowlist entry is not read as a type entry", () => {
  const allow = [{ family: "spacing", file: F, token: "--atlas-spacing-2", count: 1, reason: "x" }]
  assert.deepEqual(semanticTypeViolations([{ file: F, src: ".a {}" }], allow).violations, [])
})
```
